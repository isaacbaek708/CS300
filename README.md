# CS300
CS 300 Portfolio Reflection

The main problem I was solving in the projects for this course was how to organize, store, search, and display course information in a way that would help academic advisors access information quickly. In Project One, I analyzed different data structures, including vectors, hash tables, and binary search trees, to compare their run-time and memory use. In Project Two, I used that analysis to create working code that could load course data, sort the courses in alphanumeric order, and print course information with prerequisites.

I approached the problem by first thinking about what the program needed to do most often. Since the advisors needed to print a full course list and search for individual courses, choosing the right data structure was important. Data structures matter because they affect how fast a program can store, search, sort, and display information. For example, a vector can be simple and effective for storing and sorting course data, while other structures like hash tables or trees may be better for faster searching depending on the situation.

One roadblock I encountered was understanding how each data structure handled the same type of information differently. It took practice to compare the strengths and weaknesses of vectors, hash tables, and trees. I overcame this by breaking the project into smaller parts, reviewing the pseudocode, testing the code step by step, and checking that the output matched the assignment requirements. Another challenge was making sure the code correctly read data from the file and handled prerequisites, but testing with the provided input helped me find and fix issues.

This project expanded my approach to designing software because it showed me the importance of planning before writing code. Instead of immediately coding a solution, I had to think about the problem, compare possible approaches, and decide which structure best fit the program’s needs. This helped me understand that software design is not only about making a program work, but also about making choices that support performance, organization, and future updates.

My work in this course also changed the way I write programs to make them more maintainable, readable, and adaptable. I became more focused on using clear variable names, organizing code into separate functions, and writing comments that explain the purpose of important sections. I also learned that code should be written in a way that someone else can understand and modify later. By separating tasks such as loading data, sorting courses, printing the course list, and searching for a course, the program becomes easier to test, update, and reuse in future projects.
